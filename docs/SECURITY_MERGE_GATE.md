# Security Merge Gate: M1 (Identity, Courses, Ownership)

**Purpose:** the release gate for backend milestone M1. M1 may be marked complete, and merged, only when **every item
below passes** in CI on the merge commit.
**Authority:** derived from [`backend_security_contract.md`](backend_security_contract.md) (the contract). Rule ids
(`OWN-03`, `JWT-05`, `RT-05`, ...) refer to it; matrix ids (`I-01`, `A-05`, ...) refer to its section 10. If this
gate and the contract disagree, the contract wins and this file is corrected.
**Version:** 1.0, 2026-11-24 (before M1 implementation).

## 1. Gate rules

1. Every gate item has an automated test. Test names start with the gate id in lower case, e.g.
   `test_g1_iso_01_...`, so CI output maps one to one onto this table.
2. A gate item passes only if its test passes **without skips** on the merge commit, in the CI workflow
   (`.github/workflows/backend.yml`, all jobs green: secret scan, dependency audit, lint, types, tests).
3. No item may be waived. Changing an expected result requires a contract change first (contract section 0).
4. "Same 404" means: status 404, `Content-Type: application/problem+json`, and a body identical to the body returned
   for a random, never-issued UUID, except for `request_id`.
5. "Generic 401" means: status 401, header `WWW-Authenticate: Bearer`, and one body shared by every token failure;
   the body never names the failed check (JWT-09).
6. M0 gates stay gates: section 9 lists the M0 checks that must still pass.

## 2. Scope of M1 (what the gate covers)

| Area | Endpoints / components |
|---|---|
| Registration and login | `POST /api/v1/auth/register`, `POST /api/v1/auth/login` |
| Session | `POST /api/v1/auth/refresh`, `POST /api/v1/auth/logout`, `POST /api/v1/auth/logout-all`, `GET /api/v1/auth/me` |
| Password | `POST /api/v1/auth/change-password` (needed to prove token revocation, JWT-05 / RT-06) |
| Courses | `POST /api/v1/courses`, `GET /api/v1/courses`, `GET /api/v1/courses/{id}`, `PATCH /api/v1/courses/{id}` (rename / archive), `DELETE /api/v1/courses/{id}` |
| Components | `users`, `refresh_tokens`, `courses` tables and migration; Argon2id hashing; JWT issue/verify; refresh-token store; lockout; rate limits on auth routes; the ownership helper `get_owned` |

**Fixture used throughout:** two registered, active users **A** and **B** (role `STUDENT`), each with one course
(`A_course`, `B_course`); a third user **C** with role `ADMIN`; a clock that tests can advance.
